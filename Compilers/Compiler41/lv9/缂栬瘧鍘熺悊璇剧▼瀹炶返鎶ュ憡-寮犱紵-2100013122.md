### 1.1 基本功能

本编译器具备以下基本功能：

## 二、编译器设计

### 2.1 主要模块组成
编译器主要模块包括：

main.cpp：负责读取SysY程序并处理用户交互。
sysy.y：定义SysY语言的语法规则。
sysy.l：定义SysY语言的词法规则。

### 2.2 核心数据结构与模块设计

本编译器的核心功能包括将SysY抽象语法树（AST）转换为中间表示（IR）并进一步生成RISC-V代码。在此过程中，设计了两个主要的类：`AST2IRConverter` 和 `KoopaVisitor`，分别用于AST到IR的转换以及IR的遍历与生成。

- `AST2IRConverter` 类负责将AST中的各个节点转换为IR。其核心数据结构包括：
  - `ir_info`：用于存储生成的IR信息。
  - `symbol_table`：符号表，用于管理变量、函数等信息。
  - `while_block_stack`：用于记录当前循环块的状态。
  - 各类 `Convert*` 函数用于处理不同类型的AST节点，如`ConvertCompUnit`、`ConvertFuncDef`、`ConvertAddExp`等。

```c
class AST2IRConverter {
public:
    std::string Convert(BaseAST *ast);  // 主要转换函数
    void init();  // 初始化函数
    IRInfo ir_info;  // IR信息存储
    SymbolTable* symbol_table;  // 符号表
    std::stack<int> while_block_stack;  // 循环块堆栈
    
    // 各种节点转换函数
    std::string ConvertCompUnit(CompUnitAST *comp_unit);
    std::string ConvertFuncDef(FuncDefAST *func_def);
    std::string ConvertAddExp(AddExpAST *add_exp);
    ...
};
```

- `KoopaVisitor` 类用于遍历IR并生成RISC-V代码。其核心数据结构包括：
  - `risv_code`：用于存储生成的RISC-V汇编代码。
  - `reg_stack` 和 `reg_set`：分别用于管理寄存器栈和已使用的寄存器。
  - `function_stack`：用于维护函数调用栈。
  - 各种 `Visit*` 函数用于处理IR的不同指令类型，如`VisitReturn`、`VisitInteger`、`VisitBinary`等。

```c
class KoopaVisitor {
public:
    void Visit(const koopa_raw_program_t &program);  // 程序访问函数
    void FunctionPrologue(const koopa_raw_function_t &func);  // 函数前言
    void FunctionEpilogue(const koopa_raw_function_t &func);  // 函数结尾
    ...

private:
    std::string risv_code;  // RISC-V代码
    std::stack<std::string> reg_stack;  // 寄存器栈
    KoopaFunctionStack* function_stack;  // 函数栈
};
```

### 2.3 主要设计考虑及算法选择

#### 2.3.1 符号表的设计考虑
在本编译器中，符号表通过SymbolTable类来管理符号信息。每个符号分为常量、变量、函数三种类型，统一用SymbolInfo类型表示，支持常量、变量和函数的信息存储。

为了处理变量作用域，编译器采用了嵌套符号表结构：每个符号表通过parent和child指针连接，表示层次关系。每次查找符号时，会从当前符号表顺着parent一直查找到根节点，直到找到对应符号。
对于变量，根据翻译需要细分为函数参数、指针类型、数组类型和简单的整数类型，同时在结构体中保留了对应指针类型的嵌套层级（nested_layer）来完成lv9中相应的翻译(getptr/getelemptr)。

```c
/* 结构体用于存储常量信息 */
struct ConstantInfo {
  int value;
};

/* 结构体用于存储变量信息 */
struct VariableInfo {
  int nested_layer;
  bool is_param;     // 是否为函数参数
  bool is_pointer;   // 是否为指针类型
  bool is_array;     // 是否为数组类型
  // 其他必要的变量信息
};

/* 结构体用于存储函数信息 */
struct FunctionInfo {
  std::string type;  // 函数的返回类型
};

/* 使用std::variant来表示不同类型的符号信息，可以是常量、变量或函数 */
using SymbolInfo = std::variant<ConstantInfo, VariableInfo, FunctionInfo>;

/* 符号表类，管理和查找符号信息 */
class SymbolTable {
public:
    std::optional<SymbolInfo> getSymbolInfo(const std::string& symbol) const;
    ...

private:
    std::unordered_map<std::string, SymbolInfo> table;
    SymbolTable* parent;
    SymbolTable* child;
};

```

#### 2.3.2 寄存器分配策略
实验采用了最简单的寄存器分配策略：将所有变量存放在栈上。这种方式具有以下几个优点：

1. **Koopa IR 到 Riscv 的翻译更为简化**：由于 Koopa IR 采用 SSA（静态单赋值）形式，计算结果直接存储在栈上并与特定地址相关联。这样就不需要处理寄存器分配和活跃变量的关系，翻译过程容错性更高。
  
2. **函数调用过程中的参数传递与分配更为便捷**：无需处理复杂的调用者/被调用者寄存器保存问题（尽管自己仍然实现了调用者寄存器的保存和恢复，然后没时间完成更复杂的寄存器分配策略了orz）。

#### Lv5. 语句块和作用域
非常好语法，使语句块和作用域非常清晰（bushi）
主要内容就是在`SymbolTable`中添加`parent`和`child`指针，在查找符号时从当前符号表向根符号表查找即可，同时为每一个符号表添加`id`，用于为不同作用域中相同变量添加后缀，避免 Koopa IR 中变量重合

```c
std::optional<SymbolInfo> SymbolTable::getSymbolInfo(const std::string& symbol) const {
  SymbolTable* current = const_cast<SymbolTable*>(this);
  while (current != nullptr) {
    auto it = current->table.find(symbol);
    if (it != current->table.end()) {
        return it->second;
    }
    current = current->getParent();
  }
  return std::nullopt;
}

```
**耗时：3-4h**

#### Lv6. if语句
`Lv6`值得探讨的便是If-Else二义性问题和短路求值如何存储返回值，同时还有一个文档中没有说清晰的坑（后面讨论）

1. 先说If-Else二义性问题，解决办法非常简单——将`IfStmt`和`ElseStmt`拆开就好：
```
Stmt      :=  IF '(' Exp ')' IfStmt ElseStmt
IfStmt    :=  Stmt
ElseStmt  :=  ELSE Stmt
```
2. 短路求值中，由于Koopa IR单赋值的属性，不同分支获得的结果需要存在一个统一的变量中，这里做法是在分支跳转前用`alloc`命令分配一个变量`@x`，在短路求值失败时跳转到相应分支将结果`store`在`@x`中，并在短路求值`end`分支`load @x`获取结果
```c
  // short-circuit evaluation for LAndExp
  ret += "\t" + id_0 + " = alloc i32\n";
  ret += "\tstore 0, " + id_0 + '\n';
  ret += "\tbr " + operand_1 + ", " + if_block_name + ", " + end_block_name + '\n';
  ret += if_block_name + ":\n";
  // translate if_block
  ret += end_block_name + ":\n";
  ret += "\t" + id_2 + " = load " + id_0 + '\n';
```

3. 关于文档中没有说清楚的点，则是函数的每一个分支中虽然需要以`jump/br/ret`指令结尾，但是存在分支没有`ret`指令的情况（比如`main`函数没有`return`代码），这时需要根据当前函数的类型手动添加`ret 0`(`int`返回类型函数)/ `ret` (`void`返回类型函数)。同时分支遇到了这些命令之后应当停止翻译（`Lv7 break/continue`同理）。

**耗时：5-6h**

#### Lv8. 函数和全局变量
让人开始头疼的Lab来了，`Lv8`的主要任务是完成函数声明、函数栈地址计算和调用前的参数传递

1. 函数声明：在`SymbolTable`中添加`Function`类型的符号即可
2. 函数栈地址计算：这部分实际上文档也没有说清楚。在后端翻译过程中，栈地址的处理可以分为两部分，一部分就是在`FunctionPrologue`中计算当前函数为局部变量分配的地址，这部分是能提前处理好的，而另一部分在调用部分`call`命令这里，为了参数传递，实际上需要单独分配一块空间存储参数和调用者保存寄存器，在调用结束后需要回复栈地址指针。

`Lv9`的主要任务是完成数组和指针两种类型的支持，我们分为前端和后端分别展开：
1. 前端：Koopa IR的翻译主要引入了类型判断，数组初始化补齐 和 `getelemptr/getptr`的使用。
